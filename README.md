# BARDAHL — очередь мастеров

PWA для автосервиса: очередь по боксам, учёт работ и заказов, отчёты. Бэкенд — Supabase (таблицы `queue_*`, `work_orders`, RPC `branch_queue_action` и др.). Сборки нет: сайт статический, публикуется через GitHub Pages.

## Структура
- `index.html` — разметка и **прайс услуг** (блок `WORK_CATALOG`)
- `styles.css` — все стили (блоки идут в порядке каскада, у каждого комментарий с прежним id)
- `js/app.js` — основная логика (вход, очередь, заказы, отчёты)
- `js/clock.js`, `backgrounds.js`, `opacity-slider.js`, `rounds-clip.js`, `report-date-sync.js`, `no-zoom.js` (запрет масштабирования пальцами) — дополнения интерфейса; подключаются в этом порядке
- `install.html` — страница-ссылка для установки на главный экран (Android: кнопка, iPhone: инструкция)
- `sw.js` — service worker (офлайн-оболочка). **При изменении любого файла из списка CORE в sw.js поднимайте `CACHE_NAME`.**
- `manifest.webmanifest`, `icon-*.png` — установка как приложение (есть maskable-иконки)

## Подключение к Supabase
URL и publishable-ключ заданы в начале `js/app.js`. Ключ публичный по замыслу; безопасность обеспечивается политиками RLS на стороне Supabase.

## Управление сотрудниками
- Раздел «Сотрудники» виден только действующему пользователю с ролью `leader`.
- Руководитель создаёт только учётные записи мастеров: имя, email, временный пароль и филиал. При первом входе мастер обязан сменить пароль.
- Блокировка отзывает доступ к Auth и исключает профиль из серверной проверки роли; активное место в очереди освобождается.
- Удаление — архивирование профиля и блокировка входа. Заказы и журнал услуг не удаляются, поэтому историческая статистика сохраняется.
- Серверная функция `manage-employees` проверяет роль руководителя и использует административный ключ только на сервере. Секретные ключи не помещаются в клиентский код.
- SQL изменения находятся в `backend/employee-management.sql`; исходник Edge Function — `supabase/functions/manage-employees/index.ts`.
- Статус `is_active` и отметка архивирования проверяются не только в интерфейсе, но и в текущих RLS/RPC-путях очереди, смены филиала и записи заказов.
